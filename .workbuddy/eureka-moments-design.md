## 0. 两篇文献说了什么（先给结论，因为它们改变了架构）

### 0.1 PNAS：Tabatabaeian, O'bi, Landy & Marghetis (2025-08-18), DOI `10.1073/pnas.2502791122`

> "An information-theoretic foreshadowing of mathematicians' sudden insights"

- 用**密集行为记录**（黑板交互：书写、手势，N=4,653）追踪数学家自己系里做证明的**逐时刻活动**。
- 发现：顿悟被一个**系统无关的信息论早期预警信号**所预示 —— 黑板交互在顿悟前**变得越来越不可预测**，类比物理与生态系统中临界转变前的**临界涨落**。
- 明确对比：**文献计量是粗粒度的**，"publications are a coarse-grained record of individuals' insights"；解释顿悟必须关注**局部的、分布式的智力活动系统**。

**这对 Mimir 意味着什么（关键洞察）**：
账本的事件流**正是**这样一条离散符号序列 —— `knowledge.idea.added`、`literature.paper.imported`、`experiments.saved`…… 论文的副结论恰好说这套 EWS 适用于"**varied systems with discrete, symbolic dynamics**"。Mimir 不是在做类比，**它就是这个适用的对象类型**。

而且 Mimir 比文献计量更接近他们要的"局部密集记录"——这正是论文说必须有、而 bibliometrics 给不了的东西。

### 0.2 Stanford STORM（Shao, Khattab, Lam et al., NAACL 2024；OVAL Lab）

**真实机制**（不是网上流传的"扮演五个角色"）：
1. **pre-writing 才是全部工程量所在** —— 写作质量是检索覆盖率的下游产物，所以不优化写作阶段。
2. **视角是从数据里发现的**：先抓同类主题的真实维基条目，**挖它们的目录结构**，从真实文档反推该领域客观存在的切入视角；而不是写死几个 persona。
3. 每个视角的提问者 ↔ **必须调用检索的专家** 对话，把检索片段攒成引用库，每段都挂来源。
4. **Co-STORM（EMNLP 2024）把人拉回循环** —— 因为全自动跑完再读报告这条路不够。

**那篇公众号文章自己的反思（这是最该听的部分）**，它点名了三个致命缺陷：
- 四段提示词把 **R（Retrieval）整个删了** → "把发动机拆了留下车壳"。
- "五个视角都同意 → 大概率为真" **不成立**：它们是同一模型、同一语料、同一次采样的五段文本，误差高度相关；多数投票提升准确率的前提是**投票者相互独立**。
- "没有视角讨论的主题 = 领域空白" **不成立**：那是**模型的盲区**，不是人类知识的盲区。
- 误差被复利：2 读 1、3 读 2、4 读 3，第一步编造的事实会被后面反复加权，最后以 9/10 置信度出现；而唯一的纠错环节是让模型审自己（锚定效应最强）。
- 真正的先驱是**系统综述方法学**（Cochrane 手册 / PRISMA）：写明检索式、检索日期、命中数、纳入排除标准、双人独立提取、偏倚风险评估。
- 博士训练**不可压缩**的部分：你的论断要交给**有动机摧毁它的同行**去审。

## 1. Eureka 升级：从一阶统计量到**信息论早期预警信号**

### 1.1 现有实现的不足

`eureka.ts` 现在的 5 个特征是**一阶统计量**（新建数、事件数、会话数、净推力、活跃天数）。它们能回答"顿悟前是不是更忙"，**但回答不了"是不是更不可预测"** —— 而后者才是 PNAS 找到的那个信号。一阶量分不清"高产期"和"临界涨落期"。

### 1.2 新增：`ledger-ews.ts`（符号动力学层）

把账本当**离散符号序列**处理，直接移植论文的度量族：

| 度量 | 定义 | 对应论文里的什么 |
|---|---|---|
| `unigramEntropy` H₁ | 动作分布的香农熵 | 活动种类的发散度 |
| `conditionalEntropy` H(k) | k 阶马尔可夫条件熵（下一动作在历史条件下的不确定性） | **"increasingly unpredictable" 的可操作化** |
| `entropyRate` | H(k) 随 k 收敛的值 | 序列整体的不可预测性 |
| `surprisal` | 单事件的 −log p（给定历史） | 临界涨落的逐点痕迹 |
| `lag1Autocorr` | 符号序列（数值化后）的滞后-1 自相关 | 经典的 **critical slowing down** 指标 |
| `variance` / `skewness` | 滚动窗内统计量 | 经典 EWS 三件套 |

**为什么必须同时保留经典 EWS**：论文说的是"信息论信号"，但复杂系统里临界转变的标准预警是 **critical slowing down**（方差↑、滞后-1 自相关↑、偏度↑、闪烁）。两套指标互补，而且 Lag-1 自相关对**短序列**更稳健 —— 这点对 Mimir 很关键，因为单个研究者在一个窗口内的事件数可能只有几十条，高阶条件熵在小样本上会严重高估。

### 1.3 关键设计决策（诚实版）

- **滑动窗口 + 配对对照不变**：沿用 `[t−14d, t)` 配 `[t−28d, t−14d)`，但每个窗口现在产出的是**EWS 向量**而非一阶计数。
- **小样本必须注册**：`CBE_EWS_MIN_EVENTS`（建议 12）。低于此，条件熵不被计算（`null`），只报一阶量。这是防"几十条事件算出个 0.9 的熵率还当真"的关键闸门。
- **阶数自适应**：k 阶条件熵的 k 取 `min(2, floor(log(n)/2))` 之类，随样本量走，绝不固定 k=3 硬算。
- **仍然是描述，不是预测**：EWS 向量的输出格式统一为「你的 Eureka 前 14 天，熵率均值 X，对照窗 Y，lift Z」。**不生成"你现在处于临界状态"的提示** —— 那是从"描述已走的路"偷渡到"预测未走的路"，而且对单用户小样本，假阳性代价极高（天天喊狼来了，用户三天就关掉）。
- **验证先行**：只有**事后**（Eureka 已宣告）才做对照统计。G0 门禁不变。

### 1.4 与现有模块的接缝

`eurekaFeatures` 扩展为 `ewsFeatures`，新增字段；`CbeEurekaFeatureKey` 增加 `entropyRate` / `lag1Autocorr` / `variance` / `surprisal`。老字段保留（一阶量仍是有效描述），新字段在小样本下为 `null`。**不破坏既有测试与行为。**

## 2. 周报 = 经验胶囊（Experience Capsules）

### 2.1 从 STORM 拿什么、不拿什么

| STORM 机制 | Mimir 采纳？ | 理由 |
|---|---|---|
| pre-writing 优先 | ✅ **采纳** | Mimir 本来就是：所有报告都是对 events 的纯 fold，文采是末端 |
| **视角从数据发现** | ✅ **采纳，且是核心** | 见下 |
| 每段挂来源 | ✅ **已经是纪律** | 每条都溯源到事件 id |
| PRISMA 式溯源头 | ✅ **采纳** | 见 2.3 |
| Co-STORM 人在环 | ✅ **已经是架构** | 系统提名 / 人 pin；系统描述 / 人宣告 Eureka |
| 写死五个 persona | ❌ **拒绝** | 个人账本只有一位研究者，扮演"经济学家"是角色扮演不是视角发现；Zheng 2024 显示 persona 不能稳定提升 |
| "视角都同意→为真" | ❌ **拒绝** | 除非切片真正独立 |
| 自评打分 | ❌ **拒绝** | 自我增强偏差；Mimir 不给研究者打分 |

### 2.2 胶囊的视角从**数据**里发现（不是模板）

Mimir 的"多视角"来自**真正独立的数据切片**，因此"多切片一致"在 Mimir 里**第一次具备了论文要求的独立性前提**：

| 视角 | 数据来源 | 独立性来源 |
|---|---|---|
| 主线推进 | worktree lanes + mainline reflog | 拓扑结构 |
| 死叉教训 | `status='failed'` 的 lane + closeReason + GUT | 状态字段 |
| 文献摄入 | `library-themes` 主题漂移 | papers 表，与 events 不同表 |
| 习惯节律 | `habits` 会话/时段/连续天数 | 时间戳，与动作语义正交 |
| 值得记住的瞬间 | `moment-index` 精选层 | 爆发检测 + 人的 pin |
| 未收的尾 | `openLoops` | 事件流的开闭配对 |

这六个切片**测的是同一段时间的六个不同物理量** —— 这不是同一模型的五次采样，是六次独立测量。所以"三切片同时指向 X"在这里才有信息量。

**每个胶囊 = 一个自包含、可检索的经验单元**：
```
[胶囊] 2026-08-24 · 主线推进 · 证据 7 条
一句话：稀疏注意力在本周从第 3 次实验走到收敛态（drift +2.1）
证据：ev-041(ev-042, ev-047) · 主题：attention-sparsity
我的批注：[ 可写 ]
```
胶囊自带：时间、视角、一句话事实、证据 id 列表、可选批注。**可检索**（按视角/按线/按时间）、**可 pin**、**可导出**。

### 2.3 PRISMA 式溯源头（直接搬系统综述的纪律）

每份报告顶部固定一段"检索声明"，这正是那篇文章说被跳过、却是医学界干了三十年的东西：

```
> 本报告源：events 表 · 窗口 2026-08-18 → 2026-08-25（7 天）
> 命中事件 47 条 · 纳入 47 · 排除 0（窗口外 213）
> 派生版本 CBE v2 · habits 沉默（会话 2 < 3）· themes 沉默（论文 2 < 3）
> 本报告为描述，不含建议
```
**"沉默"要写出来** —— 哪一层的证据不够、为什么闭嘴，这本身就是 PRISMA 里的偏倚风险评估。

## 3. 项目总结 = 有设计感的 Markdown（不渲染图片）

### 3.1 直答：Markdown 能做到 HTML 那种交互和设计感吗？

**一半能，一半不能，而且边界很清楚：**

| 能力 | 纯 Markdown | GFM | HTML-in-MD | 结论 |
|---|---|---|---|---|
| 表格布局 | ❌ | ✅ | ✅ | ✅ 排版主力 |
| 任务清单 | ❌ | ✅ `- [ ]` | ✅ | ✅ Mimir 已支持 |
| **可折叠交互** | ❌ | ❌ | ✅ `<details>` | ✅ **无需 JS 的真交互** |
| 提示块 callout | ❌ | ✅ `> [!NOTE]` | ✅ | ✅ 视觉层次 |
| 图示 | ❌ | ✅ Mermaid | ✅ | ⚠️ 需渲染器支持 |
| 徽章 / 标签 | ❌ | 部分 | ✅ | ⚠️ GitHub 会剥内联样式 |
| 真交互（筛选/标签页/hover） | ❌ | ❌ | ⚠️ 需 JS | ❌ GitHub 直接剥掉脚本 |
| 字体/配色控制 | ❌ | ❌ | ⚠️ 受渲染器 CSS 限制 | ❌ 不可移植 |

**结论**：`<details>/<summary>` 是唯一"无需 JS、跨平台可用"的真交互，必须作为主力。Mermaid 能画图但依赖渲染器（GitHub/Obsidian/VS Code 都行，裸编辑器不行）。字体配色不可移植 —— 所以**设计感必须靠结构而非样式**：层级、留白、表格、callout、徽章式行内代码。

### 3.2 Mimir Markdown 子集（MMS）—— 建议定义

因为 Mimir **自己渲染** Markdown（`markdown.ts` + `MarkdownView.tsx`，目前只支持 table / input），我们可以定义一个**受控子集**，并保证优雅降级：

- **Core（到处都能看）**：标题层级、`**粗**`、表格、列表、任务清单、引用块、行内代码
- **Enhanced（GFM/HTML，不支持时降级为普通引用/列表）**：`<details><summary>` 折叠块、`> [!NOTE]/[!TIP]/[!WARNING]` callout、Mermaid 图、徽章式 `` `text` `` 
- **Forbidden**：内联 `style`、`<script>`、`<iframe>`、外部字体 —— 安全与可移植都不允许

**降级策略**：每个 Enhanced 构造都必须有 Core 等价物（`<details>` 降级为普通引用块，callout 降级为 blockquote），这样在裸编辑器里依然可读。

### 3.3 项目总结的 Markdown 结构（骨架）

```
# 项目总结 · <项目名>
> 检索声明（PRISMA 式，见 2.3）

| 跨度 | 主线移动 | 新建想法 | 死叉 | 文献 | 最长一次 |
|---|---|---|---|---|---|
| 14 周 | 3 次 | 21 | 5 | 34 | 95 分钟 |

## 这一路的形状
<details open><summary>完整工作树（Mermaid）</summary>
```mermaid
gitGraph ...
```
</details>

## 六个视角
<details><summary>主线推进（证据 12）</summary> …胶囊列表… </details>

…（文献 / 习惯 / 瞬间 / 未收的尾）

## Eureka 里程碑与它的前奏
| # | 日期 | 里程碑 | 前 14 天熵率 | 对照窗 | lift |
|---|---|---|---|---|---|
| 1 | 08-12 | 想通了瓶颈 | 1.42 | 1.11 | +0.31 |

## 值得记住的瞬间（精选索引）
| 时刻 | 线 | 类型 | 我的批注 | 证据 |

**本轮与原设计的两处偏差（均按你的指令）：**
- **不做主动临界状态提示**：原设计说"F 押后到 A–E 定稿"，你直接要求 B→F 一口气做完。但"临界提示"本身仍不做——改为 `eurekaCriticalStateData` 静默搜集每个已宣告 Eureka 的前奏 EWS（lead-in 熵 vs 对照窗），供后续分析/学习，**绝不**由此推出"你快顿悟了"。
- **Mermaid 纳入 MMS**：D 阶段把 Mermaid 作为 Enhanced 构造输出，裸编辑器降级为代码块；仅 project 层报告附带工作树 Mermaid。
